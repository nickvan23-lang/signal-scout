# Signal Scout search visibility update

Prepared November 6, 2026 (Pacific). This work updates the existing public GitHub Pages site for the iPhone app, Apple app ID `6810531496`.

This records the first pass. Subsequent technical changes, search notification automation, and account-access findings are documented in the [phase-two follow-through](SEO-AEO-PHASE2-2026-11-06.md).

## Finding that changed the work

Apple’s public U.S. catalog returned Signal Scout - BLE Finder as **Free**, version **1.3**, requiring **iOS 17.0 or later**. The existing live homepage still said “App Store review in progress” and had no App Store download link. The [dated public-catalog receipt](evidence/2026-11-06/app-store-public.json) records the source and relevant fields. Public availability is distinct from private review status or proof of which source commit shipped.

## Implemented website changes

| Area | Change and purpose |
| --- | --- |
| Download path | Official App Store links on the homepage and support page, plus the iOS Smart App Banner on those pages. Visitors can reach the available app. |
| Product description | The homepage explains the product, platform, price, broadcasting requirement, and signal-strength limits in visible text. |
| Page metadata | A clearer homepage title and description, social metadata, and descriptive headings. Existing HTTPS canonical URLs are retained. |
| App identity | A stable `MobileApplication` entity links the site to the exact Apple listing, real developer, iOS requirement, free offer, and verified version. No review or rating is invented. |
| Questions and answers | Visible answers address pricing, privacy, headphones/earbuds, powered-off devices, names/manufacturers, RSSI, and missing signals. |
| Useful guides | Three static pages address a search routine, troubleshooting, and RSSI interpretation. They use distinct topics, direct answers, internal links, and relevant primary-source references. |
| Discovery | Home and support link to every guide; the sitemap includes all six public content pages. Reviewer pages retain `noindex` and stay outside the sitemap. |
| Verification | The existing SEO checker now validates every indexable HTML page, canonical coverage, local links/anchors, parseable JSON-LD, image attributes, the real download destination, and stale release wording. |

## AEO approach and limits

The same visible product facts support people, search engines, and assistants: exact product identity, a current official listing, clear answers, and accessible static HTML. The structured data describes what is actually on the page. It does not guarantee a rich result or an AI citation. The app has no published user ratings in the captured catalog; no aggregate rating or review markup was added.

Google’s newer [generative AI optimization guide](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide?version=published), checked during this work, emphasizes useful original content and technical SEO. It does not require special AI markup, a particular writing formula, or `llms.txt`. Google says it does not use `llms.txt` for search visibility. No such file was added as a purported ranking fix.

The FAQ is useful page content. Google [retired FAQ rich results on May 7, 2026 and removed their documentation in June](https://developers.google.com/search/updates); no FAQ rich-result benefit is claimed. The app entity also lacks the genuine rating/review required by Google’s [software-app rich-result rules](https://developers.google.com/search/docs/appearance/structured-data/software-app). It describes the real product without claiming rich-result eligibility.

## Crawlers and account-level follow-up

- The effective robots URL is `https://nickvan23-lang.github.io/robots.txt`; it returned HTTP 404 during the check. A project-local `/signal-scout/robots.txt` would not configure this host’s crawlers. No host-wide crawler policy was changed.
- The six public content pages use indexable HTML. The reviewer/demo pages intentionally keep their `noindex` directives.
- Verify the URL-prefix property `https://nickvan23-lang.github.io/signal-scout/` in Google Search Console using the account owner’s verification method. Submit `https://nickvan23-lang.github.io/signal-scout/sitemap.xml` and inspect the homepage plus new guide URLs.
- Google’s current guide also calls for checking inclusion in Search generative AI features in Search Console and points to its Generative AI performance report. Those account settings and reports were not accessed or changed here. Do not infer their status from a public page fetch.
- If using Bing Webmaster Tools, verify the same site and submit the sitemap there. No Bing submission or IndexNow receipt is claimed.
- For ChatGPT search eligibility, review [OpenAI’s crawler documentation](https://developers.openai.com/api/docs/bots), particularly `OAI-SearchBot`, separately from training controls. The project has no independent host-root robots file.

## What was not measured or changed

No Google/Bing index coverage, search impressions, clicks, conversions, App Store keyword performance, or AI citation rate was available in this work. Crawlable pages and successful checks are not proof of indexing, ranking, or installs. No paid campaign, domain purchase, unsolicited outreach, or native app release is part of this website update.

The proposed App Store copy is in [the ASO brief](../AppStore/ASO-2026-11-06.md). It is a prepared metadata update, not a claim that App Store Connect has been edited. Keep the actual current store name in website markup until an App Store name change is published.
