# IndexNow setup — 2026-11-06

## Supported scope

Signal Scout can use IndexNow without controlling the GitHub Pages host root.
The official protocol's **Option 2** accepts a UTF-8 key file elsewhere on the
same host when every request includes `keyLocation`. A key in a subdirectory
authorizes URL submissions under that directory. This installation therefore
uses the following exact scope:

| Field | Value |
| --- | --- |
| Host | `nickvan23-lang.github.io` |
| Authorized URL prefix | `https://nickvan23-lang.github.io/signal-scout/` |
| Public key file | `Web/56c50f95908efbee17d74ecdd541366b.txt` |
| Public key location | `https://nickvan23-lang.github.io/signal-scout/56c50f95908efbee17d74ecdd541366b.txt` |
| Submission endpoint | `https://api.indexnow.org/indexnow` |

The key is a public verification token generated once with Python's `secrets`
module. Keep its filename and contents unchanged between deployments. This
file does not establish control over the host root or other project paths.
Source: [IndexNow protocol documentation, Option 2](https://www.indexnow.org/documentation.html).

## Deployment and submission

The script uses Python 3.9+ and its standard library. Run commands from the
repository root. Its default mode is entirely offline and sends no request:

```bash
python3 scripts/submit_indexnow.py --output /tmp/signal-scout-indexnow-dry-run.json
```

Publish the website and key file through the normal GitHub Pages deployment.
The Pages workflow automatically submits after a successful deployment. Inspect
its `indexnow-receipt` artifact before a manual submission to avoid sending the
same notification twice. If a manual submission is needed after deployment:

```bash
python3 scripts/submit_indexnow.py --submit --output /tmp/signal-scout-indexnow-receipt.json
```

`--submit` first fetches the public key URL and requires HTTP 200 with the
matching token. A failed preflight sends no POST. A successful preflight is
followed by exactly one POST. Redirects are not followed, HTTP errors are
reported, and there is no automatic retry. The script deliberately does not
poll for indexing.

By default, the script selects eligible URLs from `Web/sitemap.xml` (six at
setup). For a later change affecting only particular pages, restrict the
notification with one or more `--url` arguments:

```bash
python3 scripts/submit_indexnow.py --submit \
  --url https://nickvan23-lang.github.io/signal-scout/support.html \
  --output /tmp/signal-scout-indexnow-receipt.json
```

Only run a submission against the checkout that was successfully published.
The script checks the deployed key; it does not fetch or compare deployed HTML
with the local checkout. The Pages workflow runs `scripts/check_seo.py` before
deployment, then runs the IndexNow script after successful deployment as a
nonblocking step. It retains the `indexnow-receipt` artifact for seven days.
An indexing notification failure does not undo a successful website deployment.

## Validation and exclusions

The script validates the fixed HTTPS host and `/signal-scout/` prefix, rejects
queries, fragments, encoded paths and traversal, and requires a matching local
HTML file with an exact canonical URL. It parses a sitemap `urlset`, rejects
duplicate URLs, and limits a request to 10,000 URLs. Local pages with a robots
or bot-specific `noindex`/`none` directive are excluded. Pages under `review/`
are excluded explicitly, even if accidentally added to the sitemap.

This is a notifier for the currently published indexable HTML pages. It does
not notify deleted URLs or non-HTML assets because it requires local source
files. The protocol also supports deletion notifications, but those would
need a separate, deliberate workflow.

## Receipt interpretation and limits

Every run prints a JSON receipt. `--output` additionally writes it to the
requested path. The receipt includes UTC start and completion timestamps,
the exact URL list and request payload, excluded URLs, whether a POST was
attempted, and the HTTP response. Response headers and body are each capped
at 8,192 bytes/characters with truncation flags.

| Result | Meaning and next action |
| --- | --- |
| `dry-run-valid` | Local validation passed; no network request was made. |
| HTTP 200 / `accepted` | The notification was received successfully. This does not prove crawling, indexing, or ranking. |
| HTTP 202 / `key-validation-pending` | The URLs were received and key validation is pending. This does not prove indexing. |
| HTTP 400 | Invalid request format; inspect the receipt and payload before another attempt. |
| HTTP 403 | Key validation failed; inspect public file access and contents. |
| HTTP 422 | URLs or request fields do not satisfy protocol requirements. |
| HTTP 429 | Rate limiting or suspected excessive submissions; stop immediate retries. |
| `transport-error-delivery-unknown` | A POST was attempted but its response was not obtained; receipt does not establish acceptance or rejection. |

Exit status is zero for a valid dry-run or HTTP 200/202, and nonzero for
validation, preflight, transport, HTTP, or receipt-writing errors. Neither a
zero exit status nor acceptance guarantees search visibility.

Submit meaningful additions or content changes when deployed. Do not repeatedly
resubmit unchanged pages as a ranking tactic. The protocol permits up to
10,000 URLs per POST, and its guidance recommends avoiding repeated submissions
of the same URL within five minutes. This small site needs only one batch for
the current changes. Participating engines share submissions, so sending the
same batch separately to every engine is unnecessary. IndexNow does not submit
the sitemap to Google Search Console or verify a Search Console property.
